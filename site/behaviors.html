Behaviour guide

A species is driven by one behaviour program: either a state machine (kind: "fsm") or a behaviour tree (kind: "bt"). Both share one vocabulary of predicates (conditions) and actions, defined in schema/v0.1/behavior-program.schema.json. Most species should reach for one of the three shared programs in behaviors/ (shown in full below) and override its params; write a species-local behavior.json only when none of them fit.

Finite state machines

One state is active at a time. Each tick:

  1. Every transition is checked in priority order, highest first; ties keep the order they appear in the file. from: "*" matches any current state. The first transition whose when predicate holds fires — at most one transition per tick — and the machine moves to its to state.
  2. A state's min_dwell_s blocks any transition out of it whose priority is ≤ 0 (the default, when a transition has no priority) until that many seconds have passed in the state. Transitions with priority > 0 (for example, fleeing a threat) can always interrupt, dwell time or not.
  3. Then the now-active state's action runs for this tick. If an action fails (its target vanishes, its resource is gone), the machine returns to initial rather than staying stuck.

Behaviour trees

The whole tree is ticked from the root every tick — there is no persistent "current node" — so a higher branch can always interrupt a lower one the moment its condition becomes true.

  • selector: ticks children in order until one succeeds or is still running; used to pick the highest-priority applicable branch.
  • sequence: ticks children in order until one fails. A cond child is re-checked every tick, not just once on entry, so a sequence aborts immediately if an earlier condition stops holding.
  • parallel: ticks every child every tick; succeeds once succeed_on of them have succeeded.
  • inverter: succeeds if its child fails, and vice versa.
  • succeeder: always succeeds, whatever its child does.
  • repeat: runs its child up to repeat times.
  • cooldown_s: lets its child start at most once per that many seconds.
  • timeout_s: fails its child if it has been running longer than that many seconds.
  • cond: succeeds if its predicate holds, else fails; carries no action.
  • act: runs one action.
  • subtree: inlines another bt program's root by id.

Parameters and ${param}

A program's params block declares named values. Anywhere else in the program, a string that is exactly ${name} — the whole string, not a substring inside a longer one — is replaced by that param's value at load time. A species' behavior.params may override a value for any param the program declares; it cannot introduce new params the program doesn't know about. A seasonal.phases[].behavior_params entry can further override params only while that phase is active.

Lint rules

The validator statically checks every program:

  • Every node and action type is one the schema knows.
  • Every ${param} reference names a param the program actually declares.
  • Every declared param is used somewhere, and every ParamOrNumber value is within any range the field implies.
  • FSM: every state is reachable from initial, and every state has at least one way out (a transition whose from matches it, or from: "*").
  • No unknown call id — every sing/alarm action's call must name a call_id the species actually declares in vocalizations.
  • subtree references resolve to a real bt program id, with no cycles.
