# speeeecies: plan

speeeecies is a public kit for adding animal species to a live ecological
simulation. You, or your coding agent, write one JSON record per species:
what it is, how big it is, what it eats, when it is active, how it behaves,
what it sounds like and what its blocky 3D model looks like. A validator
checks the record, a browser previewer shows the model, and a pull request
delivers it. The simulation imports accepted records; its engine is not part
of this repository and is not needed to contribute.

Watch the simulation live: https://www.youtube.com/@jt55401/live

## Scope of v0 (format 0.1)

- **Animals only.** Plants need a data-driven plant format first; that is
  roadmap item SPEEEECIES-M8.
- One species per directory, `species/<slug>/`, where the slug is the
  scientific name lowercased with hyphens (`vulpes-vulpes`).
- Every datum is sourced. Sources carry a licence; the validator enforces a
  licence policy (below) and writes an `ATTRIBUTION.md` per species.

## The species record

`species.json` holds, in one file:

| Block | What it says |
|---|---|
| `id`, `slug`, `common_names`, `taxonomy`, `external` | Who the species is; GBIF and iNaturalist ids are required. |
| `conservation`, `range` | IUCN category; native, introduced and invasive regions (ISO 3166 codes). |
| `traits` | Mass, length, gaits and speeds, lifespan, diet shares, social group, activity pattern, defence, wariness. |
| `habitat` | Strata used, resources taken, hard placement rules, suitability curves, tolerance of people and built land, density. |
| `seasonal` | Year-round, dormant or migrating; named phases (`mating`, `dormancy`, ...) by month-day window and region; life stages. |
| `activity` | Monthly activity curves per region, generated by `tools/fetch-activity`. |
| `behavior` | A behaviour program id and parameter overrides. |
| `vocalizations` | Calls: context, months, time of day, cooldown, frequency band, a description. |
| `look` | Block-mesh body plan, proportions, palette, part colours, extra parts, poses. |
| `sources`, `provenance` | Every source with its licence; which sources back which datum. |

The format is derived from, and maps onto, the simulation's internal
records, so accepted species import without hand editing. It is
self-contained: nothing here depends on the internal format.

## Licence policy

Prefer unencumbered sources. In order:

1. CC0, public domain (and MIT/Apache/BSD for code and models): score 1.0.
2. CC BY, ODC-By: score 0.85.
3. CC BY-SA, ODbL, GPL: score 0.65.
4. CC BY-NC, CC BY-NC-SA: accepted with a **warning**, score 0.2. Every NC
   datum keeps its licence and attribution so it can be removed later.

Rejected: any ND licence (we transform data), unknown or missing licences.
The report prints each species' licence mix and a cleanliness score (0-100).
Attribution is never stripped: `tools/validate --write-attribution` writes
`species/<slug>/ATTRIBUTION.md`, and the site build writes a combined
`ATTRIBUTION.md`.

Repository licence: code under MIT (`LICENSE`); species and behaviour data
under CC BY-SA 4.0 (`LICENSE-DATA`), except data marked NC, which keeps its
source's licence.

## Behaviour programs

Two kinds share one vocabulary of predicates and actions:

- `fsm`: a state machine. Each tick the highest-priority transition whose
  condition holds fires, then the active state's action runs.
- `bt`: a behaviour tree, ticked from the root every tick.

The validator lints programs statically: known node and action types,
`${param}` references declared, parameter ranges, every state reachable from
`initial`, no state without a way out, no unknown call ids, sound subtrees.

## Monthly activity

`tools/fetch-activity` counts observations per month for a species in a
region. It asks iNaturalist and GBIF for CC0 and CC BY records first and
widens to CC BY-SA, then CC BY-NC, only when the curve would be too thin.
Where iNaturalist is missing or too sparse it falls back to GBIF occurrence
counts. Counts are divided by the same class's counts that month to remove
observer effort, normalised to a peak of 1, and written with the exact
queries, licences and the source used.

## Visual check

`tools/visual-check` renders the model in several poses and angles with a
headless browser and scores the images with BioCLIP, zero-shot, against the
species' names and a few look-alike species. It runs on CPU. Scores are
advisory: block models are stylised, so a low score is a hint to look again,
not a failure.

## How a contribution flows

1. A `species-request` issue names a species and suggests regions and data.
2. An agent claims it by commenting, then writes `species/<slug>/`.
3. `tools/fetch-activity` fills the activity curves.
4. `tools/validate species/<slug> --report` must pass; the preview must look
   right.
5. The PR carries the report. CI runs the validator again.

Details for agents are in `AGENTS.md`; for people in `CONTRIBUTING.md`.
